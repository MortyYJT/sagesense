## 1. Fresh install and permission decisions

1. Launch SageSense and record the unified setup prompt.
2. Press Back without granting anything; relaunch twice.
   - Pass: the automatic prompt does not loop.
3. Reopen setup from the onboarding card.
4. Grant notification posting, then notification access.
5. Open optional floating-warning access, grant it, return to SageSense.
   - Pass: a short preview appears once and auto-hides.
6. Grant the call-screening role if available.
7. Reopen each setting and confirm its status matches Android Settings.

Evidence file: `01-permissions-[phone].mp4`.

## 2. Message foreground/background and de-duplication

Use a test-only message such as:

```text
URGENT: verify your password now at https://secure-account-check.example
```

1. Receive it while SageSense is foregrounded.
2. Receive a changed copy while SageSense is backgrounded.
3. Trigger one immediate duplicate notification update if the messaging app
   supports it.
4. Tap the system warning or transient shield.

Pass criteria:

- each distinct message creates one event;
- an immediate identical update does not create an event storm;
- the warning opens the matching Cognitive Pause and evidence detail; and
- the app does not ingest its own output notification.

Evidence file: `02-message-flow-[phone].mp4`.

## 3. Incoming Watchlist call

The fixed `+61 400 000 999` fixture can be generated by an emulator but cannot be
spoofed safely by a normal second phone. For physical debug QA, inject the real
second phone's number into this debug APK through the ADB-only, Android
`DUMP`-permission-protected test hook:

```bash
SAGESENSE_TEST_CALLER='614_REPLACE_WITH_REMAINING_DIGITS_NO_SPACES'
adb shell am broadcast \
  -n com.mortyyjt.sagesense/.debug.DebugWatchlistFixtureReceiver \
  -a com.mortyyjt.sagesense.debug.ADD_TEMPORARY_CALLER \
  --es phone "$SAGESENSE_TEST_CALLER"
```

Open History → Watchlist and confirm a masked, clearly labelled temporary demo
entry appears. Ensure the second phone is not saved in Contacts, then call the
test phone normally. This hook exists only in the debug build and is not present
in release builds; it stores the canonical number locally and never sends the raw
number to the Agent.

Pass criteria:

- the phone continues ringing;
- SageSense shows a visible warning;
- the detail says `Local Watchlist match` and `Call not blocked`; and
- dismissing SageSense never rejects or removes the call.

Evidence file: `03-call-keeps-ringing-[phone].mp4`.

Immediately after the clip, remove the temporary fixture and confirm it disappears:

```bash
adb shell am broadcast \
  -n com.mortyyjt.sagesense/.debug.DebugWatchlistFixtureReceiver \
  -a com.mortyyjt.sagesense.debug.REMOVE_TEMPORARY_CALLER \
  --es phone "$SAGESENSE_TEST_CALLER"
```

If no second phone is available, use the isolated emulator command below and
label the footage `Seeded demo data · simulated incoming call`:

```bash
adb emu gsm call 0400000999
```

## 4. Alert sensation and overlay privacy

1. With sound/vibration enabled, trigger a real-message fixture.
   - Expect the real-message warning to be audible and vibrate once.
2. Trigger the Watchlist call.
   - Expect the phone ringtone plus one warning vibration, but no second
     notification sound.
3. Press **Send seeded demo scam**.
   - Expect no notification sound or vibration.
4. Revoke overlay access and repeat the risk flow.
   - Expect the normal notification and in-app Cognitive Pause to remain usable.

Record the observed sensation in `docs/test-report.md`; a screenshot alone cannot
prove sound or vibration.

## 5. Agent online and offline

1. Open a high-risk event and ask: `Why is this risky and what should I do?`
2. Confirm an answer, confirmation-required actions and official sources appear.
3. Enable airplane mode and ask again or reopen the flow.

Pass criteria:

- online response is relevant to the selected event and does not request secrets;
- citations open to the named official organisations; and
- offline mode retains local evidence and safe deterministic guidance.

Evidence file: `04-agent-online-offline-[phone].mp4`.

## 6. Accessibility and language

1. Switch English → Chinese without restarting.
2. Set system font scale to 1.3x and then 2.0x.
3. Turn on TalkBack and traverse Home, Cognitive Pause, detail and Settings.

Pass criteria:

- core actions remain visible or scrollable;
- bottom navigation does not clip or overlap;
- TalkBack reads risk level, evidence and actions in a coherent order;
- decorative mascot/icon content is not redundantly announced; and
- risk is never communicated by colour alone.

Evidence files: `05-large-text-[phone].mp4` and a short TalkBack observation note.

## 7. Retention and delete-all

1. Confirm History contains the test events.
2. Use delete-all and confirm.
3. Reopen History and Watchlist.

Pass: risk events are gone, while clearly labelled seeded Watchlist fixtures
remain available for the demo.

## Release decision

- **P0:** core message, ringing-call, deep-link, Agent/fallback or delete path is
  broken. Fix and rerun the full affected section.
- **P1:** permission recovery, alert sensation, overlay or accessible core action
  is unusable. Fix only if it affects the final demo phone, then rerun.
- **P2:** cosmetic/OEM issue with a clear workaround. Record as a limitation; do
  not expand scope before freeze.

Only after every P0/P1 row passes:

1. update `docs/test-report.md` with the device record and evidence filenames;
2. rebuild and recompute the APK SHA-256 if code changed;
3. push the reviewed commit;
4. create `catalyst-2026-submission`; and
5. verify the tag and downloadable artifacts from a logged-out browser.
